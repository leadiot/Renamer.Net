# Renamer：用表达式重塑文件名

批量重命名是每个开发者都逃不开的琐事：相机导出的 `IMG_20261016_0001`、爬虫抓取的乱码文档、开发目录里混杂的源文件——手动逐个改名既低效又容易出错。市面上的重命名工具大多靠"点点点"的规则配置界面，规则一复杂就难以表达，也无法复用。

Renamer 的思路不同：**把命名规则写成一行表达式**。它是一套基于 .NET 的文件批量更名工具，由核心库 Renamer.Net、命令行版 Renamer.Cmd 和图形界面版 Renamer.Wpf 三个项目组成，核心库面向 netstandard2.0，可以嵌入任何 .NET 程序。

## 一、模板表达式：一套领域专用语言

Renamer 的更名模板由**字面量文本**和**表达式**交替组成，表达式用尖括号 `<...>` 定界，字面量原样拼接进目标文件名。例如：

```text
IMAGE_<|*4><.><?>
```

可以把 `x.jpg` 重命名为 `IMAGE_0000.jpg`。拆开看：

- `<|*4>` —— 数字序列表达式，生成 4 位、左侧补零的流水号；
- `<.>` —— 条件分隔符，仅在原文件**有扩展名**时输出一个点，无扩展名文件不会产生尾随点；
- `<?>` —— 原样输出原扩展名。

这套 DSL 覆盖了几乎所有命名场景：

| 类别 | 示例 | 说明 |
| --- | --- | --- |
| 名称/扩展名引用 | `<*>` `<?>` | 输出原文件名 / 原扩展名 |
| 大小写转换 | `<*\|\>` `<*\|//>` | 文件名转大写 / 小写（Invariant 区域） |
| 管道函数 | `<*\|lower\|rep:abc:XYZ\|cut:L:1:4>` | `upper`/`lower`/`rep`/`cut`/`ins`/`del` 按序串联 |
| 数字序列 | `<\|*4:10:2>` | 位宽、起始值、步增量可调 |
| 字母/自定义序列 | `<\|?/3>` `<\|?01:2>` | 内置 a-z / A-Z，或自定义字符集（双射进制，与 Excel 列名同理） |
| 时间戳 | `<\|"c:yyyyMMdd_HHmmss>` | 当前时间 / 创建 / 修改 / 访问时间，.NET 格式串 |
| 条件分隔符 | `<.>` | 有扩展名输出点，否则输出空串 |

一个稍复杂的例子——把文件名转小写、替换字符、再截取前 4 位：

```text
<*|lower|rep:abc:XYZ|cut:L:1:4><.><?>
Abcabcdef.jpg  ->  XYZX.jpg
```

这里有一个值得一提的设计决策：模板中的特殊字符（`< > * ? " : | \ /`）**全部是 Windows 文件名的非法字符**。这意味着它们只可能出现在模板里，绝不可能从真实文件名中"漏入"，词法扫描天然无歧义，不需要任何转义机制。同时，这套语法刻意做到了**每种语义只有一种规范写法**。

## 二、Compile → Preview → Commit：三段式安全流程

直接对磁盘批量动手是最危险的。Renamer 严格遵循三段式 API：

```csharp
Renamer renamer  = Renamer.Compile(template);          // 模板非法抛 TemplateParseException
RenamePlan plan   = renamer.Preview(files, mode);        // 只读检测，不触碰磁盘
if (plan.CanCommit) plan = renamer.Commit(files, mode);  // 实际改名
```

**Compile**：模板编译为 AST 片段列表，语法错误抛出 `TemplateParseException`，错误消息附带出错字符在整个模板中的精确位置，UI 可直接定位到具体字符并给出可照做的修正建议。

**Preview**：只读检测，可反复调用，绝不触碰磁盘。检测项按文件逐项收集、互不短路，包括求值异常、空目标名、非法字符、批次内重名（大小写不敏感）、目标路径被批次外文件占用等。冲突支持两种策略：

- `Fail` —— 发现冲突即阻断提交；
- `AutoSuffix` —— 自动在扩展名前追加 ` (n)` 消解，如 `FIXED.txt → FIXED (1).txt → FIXED (2).txt`，消解记录写入 Warnings。

**Commit**：采用**同目录临时文件名的两阶段方案**。Phase 1 把待改名文件先改名为自身目录内的 `.__renamer_tmp_{GUID}{扩展名}`，Phase 1 失败自动回滚原名；全部成功后进入 Phase 2 改到最终名。这解决了交换式改名链（`a→b` 且 `b→a`）和循环改名在单趟提交下必然失败的问题，Phase 2 失败则尽力回退并上报临时路径。

## 三、一套内核，两种形态

### 图形界面（Renamer.Wpf）

Wpf 版基于 HandyControl 构建，交互严格遵循六步流程：**输入目录 → 选择更名模板 → 手动输入表达式 → 编译 → 预览 → 确认提交**。顶部的快捷标签芯片可以一键插入常用表达式片段，每类模式都有独立的可视化编辑器窗口，预览表格实时呈现原始名称、结果名称、异常信息与状态，行内删除按钮可以在提交前剔除不需要处理的文件。

![Renamer.Wpf 主窗口：表达式输入、快捷标签与预览结果](../screenshots/wpf.png)

上图中，表达式 `IMAGE_<|*4><.><?>` 正在把五个源文件预览为 `IMAGE_0001.cs` 到 `IMAGE_0005.cs`——流水号按列表顺序发号，`Ctrl+R` 可随时刷新预览。

### 命令行（Renamer.Cmd）

命令行版面向脚本与批处理场景，支持交互式输入（目录、表达式、冲突策略）和参数直调（`Renamer.Cmd 目录 表达式 [fail|auto]`）两种方式，启动时内置示例表达式提示：

## 四、架构与工程实践

```text
Renamer.Net    核心库（netstandard2.0）：TemplateParser / Pattern / Renamer / RenamePlan
Renamer.Cmd    命令行前端
Renamer.Wpf    WPF 图形前端（HandyControl）
```

几条贯穿始终的工程原则：

- **预览绝不触碰磁盘**，所有破坏性操作集中在 Commit 阶段；
- **错误可定位、可行动**——编译错误带字符位置，状态信息统一由四态 `Status`（Ok / NoChange / Resolved / Error）与 `IssueMessage` 承载；
- **语义唯一写法**，语法符号不过度复用，降低解析与认知成本；
- 七类模式（文本、前缀、后缀、时间、数字、字母、条件分隔符）各自独立成 Pattern 类，新增模式零侵入。

## 结语

重命名看似小事，却是文件管理自动化里最常见的一环。Renamer 把它抽象成一行表达式、一次预览、一次提交：规则可版本化、可复用、可嵌入你自己的 .NET 程序。如果你正被成百上千个杂乱文件名困扰，不妨让表达式替你完成这次重复劳动。

项目的后续路线还包括正则替换支持、按名称/时间排序发号、按目录复位流水号等，欢迎试用与反馈。
